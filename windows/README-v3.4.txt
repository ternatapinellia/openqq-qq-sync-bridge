OpenQQ QQ 同步桥 v3.4（Windows）

本版本重点：多官bot并发安全 + 增量同步性能优化。

============================================================
一、v3.4 修了什么
============================================================

【1】修复多官bot并发时「绑定成功却不同步」的严重问题

  现象：一个海豹挂了多个官方QQ机器人（多个群），几个群几乎同时完成绑定，
        事后发现有一部分群没有进入增量同步队列，需要重新绑定一次。

  原因：后台同步线程 sync_all() 的写法是「先读配置 -> 跑很久 -> 整份写回」。
        而绑定是「读配置 -> 加一条 -> 写回」。两者撞在一起时，
        同步线程写回的旧配置会把刚绑定的新关系覆盖掉。

  修复：只把本轮同步结果按 key 合并回最新配置，不再整份覆盖。

【2】修复配置文件写入的并发错误与垃圾文件

  现象：偶尔出现 sync_config.json 写入失败（Windows 报 PermissionError），
        并在目录里留下 .tmp 垃圾文件。

  原因：save_sync_config 没有加锁，多个线程同时 os.replace 同一个文件。

  修复：加锁 + 原子替换 + 异常路径清理 .tmp。

【3】增量同步备份节流（多官bot性能优化）

  现象：挂多个官bot时，磁盘 IO 很高；data-logs.db 有几百 MB 时尤其明显。

  原因：每跑一轮同步，都对 data.db 和 data-logs.db 各做一次全量快照。
        10 个群 x 每 10 分钟 = 每天上千次全量快照。

  修复：同一文件 600 秒内最多备份一次（首次快照永不省略）。
        绑定/迁移路径不受影响，仍然每次都备份。

============================================================
二、怎么更新
============================================================

方式一（推荐）：双击「更新OpenQQ同步桥-v3.4.cmd」
  它会自动下载发布包、备份旧文件、替换 exe 和插件，并提示下一步。

方式二（手动）：
  1. 关掉正在运行的旧桥
  2. 用新的 OpenQQ-QQ-Sync-Bridge-v3.4.exe 替换旧 exe
  3. 把 OpenQQ-QQ-Sync-v3.4.js 放进海豹 data/default/scripts，
     旧的 v3.3 js 改名加 .disabled 或直接删除
  4. 双击「启动OpenQQ同步桥-v3.4.cmd」启动
  5. 在 WebUI 里重载插件

============================================================
三、文件说明
============================================================

  OpenQQ-QQ-Sync-Bridge-v3.4.exe   同步桥主程序（需常驻）
  OpenQQ-QQ-Sync-v3.4.js           海豹插件，放到 scripts 目录
  启动OpenQQ同步桥-v3.4.cmd          启动脚本（读 bridge_port.txt 定端口）
  更新OpenQQ同步桥-v3.4.cmd          一键更新脚本
  bridge_port.txt                  桥的端口，默认 38999
  email_config.example.json        邮箱配置示例（验证码用）
  README-v3.4.txt                  本文件

============================================================
四、兼容性
============================================================

  * 与 v3.3 / v3.2 的数据完全兼容，绑定记录和同步队列都会保留。
  * 桥端口不变；bridge_port.txt、bridge_bindings.json、sync_config.json 原地沿用。
  * 升级后建议在群里发一次 .旧QQ绑定信息 确认绑定还在。
