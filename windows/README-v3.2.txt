========================================================
 OpenQQ QQ 同步桥 v3.2（Windows）
========================================================

用途：把旧 QQ（协议端）的骰子数据迁移到当前 OpenQQ（官方机器人）身份下，
     并支持之后的增量同步。解决 OpenQQ 平台身份变化后，
     原有角色卡、属性数据、日志数据无法直接读取的问题。


--------------------------------------------------------
 更新内容
--------------------------------------------------------

【版本 3.1】与 3.0 的差别

  功能上和 3.0 完全一致（含 GBK 兼容、增量同步），另修正了绑定判定。
  版本号提升只是为了区分分发包，方便确认手上是哪一份。
  从 3.0 升级到 3.1 不需要迁移数据，直接替换 exe 和插件即可，
  bridge_bindings.json 不动。

  替换步骤：
    1. 关掉旧的桥窗口
    2. 用新的 OpenQQ-QQ-Sync-Bridge-v3.2.exe 替换旧 exe
    3. 用新的 OpenQQ-QQ-Sync-v3.2.js 替换 scripts 里的旧插件
       （旧的 .js 建议改名成 .disabled，别让两个插件同时生效）
    4. 重启海豹
    5. 浏览器打开 http://127.0.0.1:<端口>/health
       确认显示 "version": "3.1"


【本次更新】绑定判定修正（重要）

  旧规则：绑定键是「旧QQ + 旧群」。
          一旦某个旧QQ绑过一次，再想绑到别的 OpenQQ 会被拒绝，
          而且同一个 OpenQQ 重复绑定同一个旧QQ也不会被拦截。

  新规则：绑定键是「旧QQ + 旧群 + OpenQQ账号 + 目标群」。
          于是：

            同一个旧QQ 绑到多个不同的 OpenQQ   -> 允许
            同一个旧QQ 绑到同一个 OpenQQ 两次   -> 拒绝（提示已绑定）

  举例：

    qq222 -> openqq444       允许
    qq222 -> openqq555       允许（同一个旧QQ，不同官 bot）
    qq222 -> openqq444 再绑   拒绝
    qq233 -> openqq444       允许

  升级兼容：旧版本留下的记录（键里没有 OpenQQ 信息）仍能被正确识别，
          不会因为换版本就允许重复绑定；绑定成功时会自动整理成新格式。


【本次更新 1】兼容非 UTF-8（GBK）的历史数据

  问题：绑定时会报错，日志里是

      sqlite3.OperationalError: Could not decode to UTF-8
      column 'name' with text 'Bryana Marist (?????).st ...'

  原因：旧版海豹在某些 Windows 环境下，把中文按 GBK 编码写进了数据库。
       桥读取时 SQLite 默认按严格 UTF-8 解码，遇到这种数据直接抛异常，
       整个绑定流程返回 500。

  修复：所有数据库连接都改用了容错解码，顺序是

      UTF-8 -> GB18030 -> GBK -> Big5 -> latin-1 -> (最后才替换字符)

        实测：角色名「Bryana Marist (测试角色).st 力量65str65...」
             现在能完整读出，中文和属性数值都不会丢。

     影响范围：绑定、角色查询（.旧QQ角色）、增量同步全部覆盖，
             不再因为个别历史数据卡死整个流程。


【本次更新 2】增量同步（v3.0 起）

  绑定成功后会自动开启定时同步，每 10 分钟一次，不再只是一次性复制。

    log     ：双向增量，只追加新条目，不改已有内容
    角色卡  ：旧QQ -> OpenQQ，只增不改，已有的按 id 跳过
    PC 数据 ：OpenQQ -> 旧QQ 单向回写，只有 OpenQQ 那边更新时才覆盖，
             覆盖前自动备份

  相关指令：

    .旧QQ同步状态        查看是否开启、间隔、上次跑的时间和结果
    .旧QQ立刻同步        马上跑一次，不用等 10 分钟
    .旧QQ同步开关 开/关  开启或关闭本群的自动同步

  注意：增量同步无法处理删除。旧群里删掉一条消息，另一边不会跟着删。
       并且要求旧群数据仍在同一个海豹库里（桥只读数据库文件，不连服务器）。


【本次更新 3】修复迁移后角色卡面板显示为空

  之前版本会清空「指向他人角色卡」的绑定，但海豹允许同群共享角色卡，
  绑定被清空后面板就没东西显示了。v3.0 改为保留原绑定。
  数据本身一直没有丢失。


--------------------------------------------------------
 目录里有什么
--------------------------------------------------------

  OpenQQ-QQ-Sync-Bridge-v3.2.exe   数据同步桥（主程序，需常驻运行）
  OpenQQ-QQ-Sync-v3.2.js           海豹插件，放到海豹的 scripts 目录
  bridge_port.txt                  桥的端口，插件按这个端口连桥
  bridge_bindings.json             绑定记录（自动生成，不用手动改）
  README-v3.2.txt                  本文件


--------------------------------------------------------
 使用步骤
--------------------------------------------------------

1. 放文件
   把 OpenQQ-QQ-Sync-Bridge-v3.2.exe 和 bridge_port.txt
   放到海豹目录下（和 sealdice-core.exe 同级）。

   把 OpenQQ-QQ-Sync-v3.2.js 放到

       data\default\scripts\

   如果里面有旧版本的 OpenQQ 插件（比如 OpenQQ-QQ-Sync-v2.0.js），
   把它改名成 .disabled 或移走，避免两个插件同时生效。

2. 设置端口
   编辑 bridge_port.txt，写一个端口号，例如 38999。
   如果一台机器上跑多个海豹实例，每个实例的端口要不一样
   （比如 38999 / 39000 / 39001）。

3. 启动桥
   直接双击，或在命令提示符里：

       OpenQQ-QQ-Sync-Bridge-v3.2.exe --port 38999

   看到这类输出说明成功：

       Bridge listening on 127.0.0.1:38999

   保持窗口开着，不能关闭。

4. 海豹里写插件端口
   打开海豹 WebUI -> 扩展 -> OpenQQ 旧QQ完整数据迁移，
   把「Bridge端口」改成和 bridge_port.txt 一样的值，保存。

5. 重启海豹
   让它加载 v3.0 插件。日志里出现下面这行说明加载成功：

       正在加载脚本「summer_pinellia@DNT:OpenQQ旧QQ完整数据迁移-多海豹使用:3.1」

6. 验证
   浏览器打开 http://127.0.0.1:38999/health
   看到 {"ok": true, "version": "3.1", ...} 就说明桥正常。


--------------------------------------------------------
 绑定与迁移
--------------------------------------------------------

在目标 QQ 群里执行：

    .旧QQ绑定 <旧QQ号> <旧群号>

例如：

    .旧QQ绑定 2522629086 1081354778

桥会往「旧QQ号@qq.com」发一封含 6 位验证码的邮件。
收到后执行：

    .旧QQ验证码 <6位验证码>

验证码 5 分钟有效，最多错 5 次。
验证通过后才会真正执行数据迁移。

绑定完成后可以直接用：

    .st     查看属性
    .pc     查看角色卡
    .log    查看日志（旧 log 可以用 log get+名字 取出）

注意：
  - 同一个「旧QQ + 旧群」只能绑定一次，重复绑定会被拒绝
  - 一个旧QQ号可以绑定到多个群，分别查询 log
  - 邮件功能需要在海豹插件配置里填发件邮箱、SMTP 授权码、
    SMTP 服务器和端口
  - 「SMTP授权码」不是邮箱登录密码。
    QQ 邮箱一般用 smtp.qq.com:465 + 授权码


--------------------------------------------------------
 常见问题
--------------------------------------------------------

问：绑定时报 "Could not decode to UTF-8 column"
答：这是旧数据编码问题，v3.0 已修复。
    确认你跑的是本包里的 v3.0 exe，而不是旧版。

问：桥启动后马上闪退
答：多数是被 Windows 安全中心或防火墙拦截，
    放行该程序即可。也可能是端口被占用，
    换一个 bridge_port.txt 里的端口。

问：海豹里执行 .旧QQ绑定 提示连不上桥
答：按顺序查：
    1. http://127.0.0.1:<你的端口>/health 能不能打开
    2. 插件配置里的 Bridge端口 和 bridge_port.txt 是否一致
    3. 桥的窗口是否还开着

问：角色卡变成空的，或者 log 绑定失败
答：文件只读取海豹的 data 和 datalog 里的 db 文件。
    数据库本身损坏时会出现这种情况。
    可以用原始备份的 db 文件替换，然后删掉同名的 -wal 和 -shm 文件，
    海豹再次启动会自动生成干净的 wal/shm。
    data 文件在数据转换前会自动备份，后缀是 beforexxxx。

问：一台机器怎么跑多个海豹
答：每个海豹一个目录、一份配置，
    端口（bridge_port.txt）必须各不相同。
    建议每个实例都设成开机自启。


--------------------------------------------------------
 设为开机自启
--------------------------------------------------------

在「任务计划程序」里新建任务：

  常规：勾选「不管用户是否登录都要运行」和「使用最高权限运行」
  触发器：新建 > 启动时
  操作：启动程序
        程序或脚本：<你的海豹目录>\OpenQQ-QQ-Sync-Bridge-v3.2.exe
        添加参数：  --port <你的端口>
        起始于：    <你的海豹目录>

海豹本身也建议一起设成自启，否则重启后骰子不在线。


--------------------------------------------------------
 提醒
--------------------------------------------------------

  - 本版本仍无法处理「删除」类同步。
  - 迁移前建议先备份海豹的 data 与 datalog 目录。
  - 桥只读取数据库文件，不连接服务器，不影响海豹正常运行。
