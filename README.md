# OpenQQ QQ Sync Bridge v3.3

**旧 QQ → OpenQQ 数据迁移工具**

把旧 QQ 的角色卡、PC 数据、log 搬到你的 OpenQQ 账号。

## 三步上手

**1. 装插件**

把 `OpenQQ-QQ-Sync-v3.3.js` 放进海豹的 js 插件目录，重载插件。

**2. 启动同步桥**

- Windows：把 `OpenQQ-QQ-Sync-Bridge-v3.3.exe`、`启动OpenQQ同步桥-v3.3.cmd`、`bridge_port.txt` 放到海豹主程序目录（和 `data` 文件夹平级），双击 cmd，**窗口保持开着**。
- Linux：
  - 海豹装在 Docker 容器里 → [docker/README-Docker海豹部署.txt](docker/README-Docker海豹部署.txt)
  - 海豹直接装在宿主机上 → [docker/README-DOCKER.txt](docker/README-DOCKER.txt)

**3. 在群里迁移**

```
.旧QQ绑定 <旧QQ号> <旧群号>      → 去旧QQ邮箱收验证码
.旧QQ验证码 <6位验证码>          → 完成
```

## 插件配置填什么

| 配置项 | 填什么 |
| --- | --- |
| 发件邮箱 | 你的 QQ 邮箱，如 `123456@qq.com` |
| SMTP授权码 | QQ 邮箱的 **SMTP授权码**（不是登录密码） |
| SMTP服务器 | `smtp.qq.com` |
| SMTP端口 | `465` |
| Bridge端口 | `38999` |
| Bridge主机 | Windows 填 `127.0.0.1`；Linux 同机也填 `127.0.0.1` |
| Bridge访问令牌 | Windows 留空；Linux 填 `.env` 里设的那串 |

先跑一次 `.旧QQ邮箱测试` 确认能收到邮件。

### SMTP 授权码怎么拿（必看）

验证码是桥用你填的**发件邮箱**发出去的，所以这个邮箱必须先开通 SMTP，
并生成一个**授权码**——它不是 QQ 登录密码，填密码一定失败。

**注意**：授权码属于**发件邮箱**。收验证码的是 `旧QQ号@qq.com`，
那个邮箱什么都不用设置。

1. 电脑浏览器打开 https://mail.qq.com ，登录你要当发件箱的 QQ 邮箱
2. 左上角 **设置 → 账号**（有的版本叫「账户」）
3. 往下找到 **「POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV服务」**
4. 在 **「IMAP/SMTP服务」** 那一行点 **开启**
   （开 POP3/SMTP 也行，两个开一个就够，推荐 IMAP/SMTP）
5. 按提示用绑定手机发一条短信，发完点「我已发送」
6. 通过后会显示一串 **16 位授权码**，形如 `abcd efgh ijkl mnop`
   **只显示这一次**，先复制下来
7. 回到插件配置填写：

   | 配置项 | 填什么 |
   | --- | --- |
   | 发件邮箱 | 你刚才登录的那个邮箱，如 `123456@qq.com` |
   | SMTP授权码 | 那 16 位，**去掉空格**，变成 `abcdefghijklmnop` |
   | SMTP服务器 | `smtp.qq.com`（不用改） |
   | SMTP端口 | `465`（不用改） |

8. 保存后，在群里发 `.旧QQ邮箱测试`，能收到测试邮件就说明配好了

**容易踩的坑**

- 填 QQ 登录密码 → 一定失败，必须用授权码
- 授权码里的空格要去掉
- 找不到授权码了：回到第 4 步点「生成授权码」可以重新生成，旧的会失效
- 改过 QQ 密码后授权码通常会失效，需要重新生成
- 同一个发件邮箱可以给多个海豹实例共用
- 收不到邮件时，让对方检查 QQ 邮箱的 **设置 → 反垃圾**，
  必要时把发件邮箱加进白名单

## 要注意的

- **迁移只做一次**，之后旧群的新消息不会跟过来。
- **`旧QQ号 + 旧群号 + OpenQQ账号 + 目标群` 这个组合只能绑一次**。
  同一个旧 QQ 可以绑到**多个不同的 OpenQQ 账号**，不用先解绑；
  只有完全相同的配对再次绑定时才会被拒绝。
- 验证码 **5 分钟**有效，最多输错 5 次。
- 迁移前会自动备份，备份就在海豹的 `data/default` 里。
- **迁移后不会持续同步**，旧群的新消息不会跟过来（详见下一节）。

## 迁移之后会自动同步（v3.0 起）

第一次迁移仍然是一次性快照复制，但**绑定成功后会自动开启增量同步**，
之后每隔 10 分钟跑一次，把两边新增的内容补过去。

详见下面的「增量同步」一节。

> 注意：同步桥只读海豹的数据库文件，不连 QQ/OpenQQ 服务器。
> 所以只有两边数据都在**同一个海豹库**里时才能同步。


## 增量同步（v3.0 起自动开启）

绑定成功后，**自动开启**定时同步，每隔 10 分钟跑一次。

同步什么：

| 内容 | 方向 | 规则 |
| --- | --- | --- |
| log | **双向** | 只追加新条目，不改已有内容 |
| 角色卡 | 旧QQ → OpenQQ | 只增不改，已有的按 id 跳过 |
| PC 数据 | **双向，按字段合并** | 两边独有的字段互相补齐；同名字段谁更新用谁 |

也就是说：旧群新打的团会自动出现在 OpenQQ 这边，OpenQQ 这边新打的
也会回流到旧群，但**不会覆盖或删除**任何已有记录。

### 三条新指令

| 指令 | 作用 |
| --- | --- |
| `.旧QQ同步状态` | 看同步是否开启、间隔多少、上次跑的时间和结果 |
| `.旧QQ立刻同步` | 马上跑一次，不用等 10 分钟 |
| `.旧QQ同步开关 开/关` | 开启或关闭本群的自动同步 |

### 为什么要这样设计

- **log 只追加**：log 是按时间一条条记录的，追加最安全，不会误删
- **PC 按字段合并**：两边各自独有的字段都会保留（比如旧QQ 有力量、OpenQQ 有侦查，
  合并后两边都有）；只有同名字段冲突时才比较更新时间，谁新用谁
- **角色卡只增不改**：避免把你在 OpenQQ 上改过的卡冲掉

### 注意

- 增量同步**不能处理删除**。旧群里删了一条消息，另一边不会跟着删
- log 的"新条目"是按**条目数**判断的：只在末尾追加能识别，中间插入不会
- PC 合并以**整行**的 `updated_at` 作为该行所有字段的时间依据
  （海豹不给单个字段存时间戳）
- 同步依赖**旧群数据还在同一个海豹库里**。桥只读 sqlite 文件，不连服务器
- 每次同步前都会自动备份，出问题能用 `.snapshot-first.bak` 还原

## 时间戳修复工具（可选）

早期版本有个 bug：写入 `updated_at` 时用了**毫秒**，而海豹统一用**秒**。
这会让"谁更新"的判断失效。

现在的程序已经修好（比较时会自动归一化），所以**不修也能正常用**。
但如果你想让数据干净一些，可以跑这个工具：

```sh
# 先预览，不改任何东西
python tools/normalize_timestamps.py 路径/data.db

# 确认后实际修改（会自动备份）
python tools/normalize_timestamps.py 路径/data.db --apply
```

工具做的事：
- 扫描所有 `*_at` / `*_time` 字段，找出大于 `1e11` 的值（毫秒）
- 除以 1000 变成秒
- 修改前自动备份成 `data.db.before-tsfix-<时间>.bak`
- 只改时间戳，不碰任何业务数据

> 建议先用海豹的备份或桥生成的 `.snapshot-first.bak` 备份一次再跑，
> 稳妥起见。工具自己也会再备份一遍。

## 换过 OpenQQ 账号怎么办

同一个旧 QQ 可以直接绑到多个 OpenQQ 账号，**不需要先解绑**。

如果你之前用**另一个** OpenQQ 账号迁移过，那份数据在那个账号名下，
不会跟着你换账号。

**怎么确认数据在哪**

1. 用旧账号登录 OpenQQ，`/旧QQ绑定信息` 看绑定
2. 或者直接去之前迁移时用的那个群里，看角色面板有没有数据

**怎么迁到新账号**

不需要解绑，直接切到**新账号**，在**新群**里执行：

```
.旧QQ绑定 <旧QQ号> <旧群号>
.旧QQ验证码 <6位验证码>
```

注意两点：

- 迁移是**复制**，旧账号的数据不会被删除，两份都存在
- 如果旧群属性绑定的角色卡属于旧账号，新账号的群属性会**保留这个绑定**
  （海豹允许同群共用卡）。如果那张卡在新账号看不到，面板可能是空的——
  这是海豹的显示规则，不是迁移把数据弄丢了

**排查"角色卡显示为空"**

先确认数据到底在不在，占位最少的做法：

1. 用 `.旧QQ角色 <旧QQ号>` 看那个旧 QQ 名下有几张卡
2. 卡在但面板空 → 是绑定/共用卡的问题，不是数据丢失
3. 卡本身就没内容 → 那个群里本来就没打过 `.pc`，换个有数据的群号再绑

> 同一个旧QQ，在不同群里的 `.pc` 数据是**分开存的**。
> 你在 A 群打的 `.pc`，去绑 B 群是拿不到的，必须绑 A 群。

## 从 v2.0 升级

**这是原地升级**：配置和绑定记录都会保留，不用重新绑定。

1. 关掉旧的同步桥窗口
2. 用 v3.3 的文件替换旧的（**旧的 `OpenQQ-QQ-Sync-v2.0.js` 一定要删掉**）
3. 重启同步桥，重载插件

> v3.3 的插件沿用 v2.0 的插件标识，所以能被海豹识别为同一个插件。
> 但如果两个 js 文件同时存在，海豹只会加载先读到的那个，可能导致
> 「看起来升级了、实际还是旧代码」。所以务必删掉旧 js。

详细步骤见 [升级说明-v2到v3.txt](升级说明-v2到v3.txt)。

## v3.0 改了什么

**修了一个会导致角色卡显示为空的问题。**

之前版本在迁移时会检查"群属性绑定的角色卡是不是自己的"，
不是就清空绑定。但海豹允许同一个群共用角色卡，
清空后面板就没东西显示，看起来就是"角色卡全空了"。

v3.0 改成：**保留原来的绑定**；如果这张卡本次一起被复制了，
就指向新复制的那张。数据本身一直没丢，只是显示的问题。

其它改进：
- 源群属性只认属于该旧QQ自己的记录，不会误用别人的
- 目标群已有真实数据时不再覆盖
- 数据库索引损坏时自动绕过，不会整个迁移失败

## 安全

- 同步桥只读写本机的海豹数据库文件，**不上传任何数据**。
- 验证码通过你自己配置的邮箱发出，不经过第三方。
- Windows 版只监听 `127.0.0.1`，别的机器访问不到。
- Linux 版必须设访问令牌。
## v3.0 修复：兼容 GBK 编码的历史数据

旧版海豹在某些 Windows 环境下会把中文按 GBK 编码写进数据库。
桥原本按严格 UTF-8 解码，遇到这类数据会直接抛异常：

```
sqlite3.OperationalError: Could not decode to UTF-8
column 'name' with text 'Bryana Marist (?????).st ...'
```

结果是绑定失败并返回 HTTP 500。

现在所有数据库连接都使用容错解码，顺序为
UTF-8 → GB18030 → GBK → Big5 → latin-1，最后才做字符替换。
影响范围包括绑定、角色查询和增量同步。

同时 v3.0 起绑定成功后会自动开启增量同步（每 10 分钟一次）：

- log：双向增量，只追加新条目
- 角色卡：旧QQ → OpenQQ，只增不改
- PC 数据：OpenQQ → 旧QQ 单向回写，覆盖前自动备份
## v3.3 修复：database 连接泄漏

`lookup()` 曾使用 `with self.connect(...) as con:`。Python 的 sqlite3 中
`with` 只提交事务、**不会关闭连接**，因此每次查询都会泄漏一个连接。

泄漏的连接一直持有读事务，阻塞海豹的 WAL checkpoint，导致 `-wal` 持续膨胀，
海豹读取自己的数据库时出现 1~4 秒的 `SLOW SQL`，进而拖慢回复，
偶发因超过 QQ 被动回复窗口而发不出消息。

现已改为 `try/finally` 显式 `con.close()`。升级后建议重启一次海豹，
让已膨胀的 `-wal` 立即回收。
